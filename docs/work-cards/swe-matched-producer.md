# Matched repository producer

Owner goal: one conventional and one Reparodynamic SARA attempt on each of the
unchanged ten SWE-bench Multilingual pilot tasks. This work card is preparation,
not a spending grant. No paid execution is enabled by this document.

## Shared execution contract

Use one repository coordinator and one Luna model adapter. Both arms receive the
same public issue, starting commit, dependency image, tool set, reasoning level,
and finite limits for calls, tokens, tool steps, tests, time and spend. Resolve
those limits and the model price snapshot into a source-bound registration before
requesting a fresh exact allowance. No provider fallback or speculative worker.

Every task/arm begins with empty private context and an isolated repository
session. Always make an issue-driven initial solution attempt, even if the
starting public tests pass. Hidden tests and reference repairs may not be used
to fabricate a producer-visible failure. Public compilation and tests guide
subsequent work; a passing public suite is never official acceptance.

The conventional arm uses the normal inspect/edit/test continuation. The
Reparodynamic arm must actually execute bounded strategy selection, negative
lessons, duplicate-tactic suppression, and champion/rollback decisions. Reuse
SARA's pure repair policy and governance helpers through repository-specific
signals; do not cast a complete project into the restricted TypeScript format.
The same outer ceilings apply. Record decisions and exact resulting patches so
the comparison is more than different prompt labels.

## Authority and accounting

Integrate a kernel-issued one-use permit bound to the job, task, arm, source,
environment and fresh grant. Recheck active owner and emergency-stop epoch at
every provider dispatch and before acceptance. Caller-declared zero cost is not
a permit. Do not change the existing paid rejection until this path is tested.

Reuse the owner launch/readiness and durable benchmark execution claim. Extract
parameterized reservation machinery from the existing benchmark budget with its
historical wrapper unchanged. Reuse CodingDispatchJournal at the actual fetch
boundary. No second ledger, no synthetic revenue authorizing paid jobs, no old
activation, consumed allowance, or Telegram budget. An uncertain dispatch keeps
its reservation and closes further spending; later rows remain explicitly unrun.

A runner must have durable claims and owner authority as well as Docker. The
current disposable GitHub qualification jobs contain no provider credentials and
are not an authorized paid execution host. Do not silently move secrets into CI.

## Acceptance and evidence

Freeze all twenty planned producer outcomes before judge results are revealed.
Judge only the frozen kernel artifacts in independent containers. Record failed,
empty and unrun outcomes, elapsed setup/model/tools/verification/grading time,
request counts, accounted usage, unreconciled exposure and official reports.
Published reference controls remain labeled controls and never populate results.

Required tests include public-green initial attempts; actual arm-policy
separation; task/source/image/consumed-permit rejection before network; stop and
resume revocation during generation; judge-data and extra-field exclusion;
budget consumption on invalid outputs/retries; exact rollback and rebuilt
artifacts; judge-result isolation; and preservation of every planned result.
Existing historical live grants must remain source-drift rejected.

Completion requires all ten public environments and all ten official positive
and negative controls to qualify under the selected policy, then a scripted
end-to-end comparison through the real kernel path. Only after that evidence and
an exact fresh allowance may any of the twenty paid attempts start.
