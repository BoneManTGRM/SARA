# Repository executor qualification

Owner request: execute the frozen ten-task SWE-bench Multilingual comparison
using conventional SARA and Reparodynamic SARA with the same Luna and limits.

First delivery is a separate, non-promotable repository verification boundary.
Do not widen the existing TypeScript candidate format. The kernel must authorize
admission, dispatch and acceptance, reject an intervening emergency-stop epoch,
and preserve failure receipts. No global repair memories enter this path.

Acceptance criteria:

1. Immutable environment identity, exact base commit and public task bind every
   patch. Prepared environments contain only public base sources/dependencies;
   reference repairs, hidden tests and provider credentials are judge-only.
2. Inspection, editing and public tests run inside bounded Docker containers;
   no host repository execution, host mounts, network, capabilities or secrets.
   Final verification starts a separate container from the frozen environment.
3. Freeze patch bytes before verification. Verify base and working tree, reject
   unsafe patch paths and symlink/submodule modes. Persist patch, environment,
   test command, output and hashes before a kernel completion receipt.
4. Repository acceptance never creates a production-promotable mutation or a
   SWE-bench resolved claim. Official grading remains a separate frozen-patch
   stage, with all 20 results (including failures) required for a pilot score.
5. Compare isolated task/arm namespaces with identical model and finite limits.
   A fresh, source-bound grant must reserve the entire run before any provider
   call. No old grant, monthly ceiling, or synthetic ledger funds real calls.

Qualification: adversarial patch and authority tests, actual Docker fresh-state
positive/negative controls, then full npm run verify. Passing unit tests without
Docker execution is not executor qualification. No paid launch until that gate
and an exact fresh allowance are both satisfied.

Scope of this candidate: public test commands execute in a fresh container, but
the candidate can edit public tests. A zero exit status is not proof of issue
resolution. Official judge-owned test integration is still required. Generator
callbacks are trusted host code, as in the existing kernel; their declared cost
is not a sandbox that prevents a malicious callback from making network calls.
Only the supplied deterministic qualification producer is asserted to use no
model calls. Paid generation remains unavailable in this candidate.
