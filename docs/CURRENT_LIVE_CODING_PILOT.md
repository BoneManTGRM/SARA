# Owner-requested current coding-component live pilot

This is one newly authorized, one-use, $0.15-total comparison ($0.075 each arm)
on the existing SARA operator. It is a LAB pilot, not general speed qualification.
The unresolved historical hold and every earlier consumed grant remain separate.

The task is the previously used freeWindows scheduling repair. The exact source
and protected acceptance tests are reused, not selected after model output. They
are included internally for the current digest contract but excluded from prompts
and from protected-test diagnostic details. It is not an unfamiliar-task sample.
Both arms have up to three proposals, equal model/reasoning/token/spending caps,
rollback and the same within-task lesson information. No prior solution is seeded.
The fixed order is Reparodynamic then conventional; one pair cannot remove order,
provider, response-length or stochastic generation variation.

The conventional arm uses SARA's existing bounded conventional retry-and-memory
controller, original full-file model adapter, and default TS5 loop verifier. The
current arm uses the unchanged active controller, adaptive format selector and
native PR120 intermediate verifier. Both must pass a fresh optimized original TS5
final check, followed by a separate default TS5 compilation/behavior verification.
The experiment-local runner is a byte-checked copy of the frozen runner with only
an explicit final-verifier callback added. Existing historical callers are unchanged.
A provisional native PASS can never authorize a successful final receipt.

This pilot runs the coding components on the actual deployed host with real model
responses. It does NOT create production kernel jobs/mutations, promote generated
code, preload production memory, or exercise durable reuse, HTTP job creation or
concurrent cold coalescing. Those costs/benefits are not in its arm timings. It is
not an end-to-end owner-job SLA measurement or an all-Reparodynamics-off control.
The small starting source normally selects full-file output for both arms; actual
format decisions are recorded, not assumed to exercise the compact path.

Exact PR120 implementation files are hash-pinned; the experiment registration and
executed revision are distinct and recorded. Source drift or missing native checker
blocks before consuming the paid execution claim. Same existing durable journal,
exclusive launch/execution claims, pre-dispatch request reservations, authority
checks, original provider usage, immutable failures, and read-only evidence export
remain. Unknown spending is retained, never released based on missing evidence.
No automatic paid replay is allowed. A GET of readiness may recover terminal data
but cannot resume work. A new UUID is not itself an authorization.

Local tests use scripted responses and are never labeled live benchmark results.
The live workflow must be exact-SHA bound via the existing narrow GitHub OIDC relay
and a short-lived permit. It must perform GET readiness, one POST only when ready,
and GET recovery. It must never include owner/provider credentials or alter grants
itself. Leave deployment auth, budgets, existing service/volume and NICO untouched.
